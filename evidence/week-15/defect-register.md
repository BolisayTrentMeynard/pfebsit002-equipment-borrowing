## How the overflow cause was established (DEF-09)

The test output gave the size of the overflow and the test line, not the widget. Claude inferred the app bar from the code. The narrow test passing after the fix supports that inference; the overflow location was not confirmed directly.

## Not defects (documented, not fixed)

- **W5, double-submit race in `store()`:** worst case is a second PENDING request. `release` locks the item row and answers 409 when the item is not available, so no item can be loaned twice. A single-threaded `php artisan serve` cannot honestly reproduce a race (R13).
- CORS regex accepts any localhost port (R15). `$guarded = []` on `ApiToken`, `AuditLog` and `ReminderNotification`; they are only written by internal code (R16).
- Recipient fields on `/manual-handling` were not reviewed (R14).
